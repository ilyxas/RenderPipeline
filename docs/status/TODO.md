## Высокий приоритет

### 1. Нет коллизий рук с телом и друг с другом — подтверждено
- **Симптом:** скрещённые руки проходят друг сквозь друга (клип `066332e1`, оба солвера); на других клипах «руки исследуют органы».
- **Почему:** в пайплайне нет ни одной проверки рука–рука; surface QA проверяет только кисть против одежды, на 5% кадров, и на открытых деталях корсета пишет «unavailable».
- **Решение-кандидат:** коллизии по живой коже Xandra, как в legacy `~/codex/clip_full/scripts/02b_collide.py` + `collide_lib.py`; альтернатива — оболочки `HumanoidAlpha/assets/collision/*.obj`. Требует обсуждения дизайна.
- **Что известно о legacy-решении (от Blender Assist, 2026-10-12; автор кода — «AI Trends»):** препятствие — реальная скинованная кожа (`b_dump_body.py`, top-4 LBS как в GLB): торс без вершин рук (вес <0.5), бёдра, шея/лицо; дыры закрыты → inside-тест libigl winding number + расстояние до поверхности; одежда — толщина по вершине (`cloth_max` 3 см) + зазор 3 мм. ~1270 точек на руку (локоть, предплечье, кисть, пальцы), вторая кисть тоже препятствие. Решатель — затухающий Gauss–Newton на кадр по плечу (3), локтю-петле (1, ось из данных), запястью (2); точки кладутся на поверхность; контакт ладоней — сначала левая наружу, правая к ней с зазором 2 мм. По времени — 11 раундов «гаусс-сглаживание + пересчёт» (σ 2.5×8, 1.5×3), финальный проход гарантирует зазор ≥0. Результат на clip02 (449 кадров): кадры с проникновением L/R 206/22 → 0/0, max 92.6 → 0 мм; ~4.5 мин CPU. Слабости: большие коррекции левой руки (плечо до 38.5°, запястье до 40°, скачок до 16.5° за кадр) — ладонь уходит от трекинга; нет палец–палец, кисть–другое плечо, волосы, одежда; проверялось только на кадрах, не в видео. Их же советы: решать в пространстве IK-цели с pole, гейты по остаточной глубине и угловой скорости, отсекать шумные кадры источника.

- **Эксперимент 2026-10-12 (066332e1, Viggle, `--surface-qa all`, `runs/collision-exp/20261012-023507-7a3b6776`, `tools/collision_report.py`):** новые улики по коже (`2a044a3`) находят проникновение «рука–тело» на 98/145 кадрах (max 36.5 мм) и «рука–рука» на 107/145 (max 28.3 мм), в rest-позе 0 улик. Существующее одно уточнение (толчок запястья вдоль одной нормали, покадрово, 5°) сделало хуже: рука–тело max 45.8 мм, рука–рука без изменений, +8.1°/кадр к скачкам; пайплайн его отклонил → `needs_review`. Следующий шаг (дизайн, согласовать с Codex): многоточечное уточнение плечо/локоть-петля/запястье против всех улик сразу, со скоростью/ускорением внутри решения на окне.

- **Stage-15 vertical slice (`1711947`, 066332e1):** оконное многоточечное уточнение по решению Codex. Тело: p95 25.1 → 10.4 мм; рука–рука без изменений → отклонено одним гейтом из 10, `needs_review`. Диагностика с пределом 45°: тело почти исчезает (p95 7.3), рука–рука снова без изменений → проблема в направлении выталкивания для arm_arm (к ближайшей точке = вбок), а не в бюджете. Предложено: нормаль скрещивания + выход по лучу; ждёт ревью Grok (CGC.txt 04:10, 04:25).

### 2. `video`: глубина угадывается, руки уходят вперёд — подтверждено
- **Симптом:** при подъёме руки через сторону кисть в конце на 20–27 см впереди плеча (видно сбоку в HumanoidAlpha).
- **Почему:** глубина из MediaPipe world (сам трекер даёт ~20 см) + «добивка» длины кости с зашитым знаком «к камере» (`image_body.py`).
- **Решение:** для качества — Viggle/другой 3D-источник; для `video` — убрать знак по умолчанию к камере, считать полноразмерную на картинке кость лежащей во фронтальной плоскости.

### 3. `video`: калибровка по нейтральной позе подгоняет человека к rest Xandra — подтверждено
- **Симптом:** локоть Xandra согнут на 34–37° при прямой руке человека, сгиб «плывёт» при подъёме, плечо крутится по ложной плоскости сгиба.
- **Почему:** поправки «нейтраль = rest» задаются в мировых координатах на каждую кость; сгиб локтя Xandra в rest не виден спереди, поэтому калибровка срабатывает.
- **Проверено:** `XMS_NEUTRAL_CALIBRATION=0` делает сгиб как у человека, но прокрутка плеча начинает шуметь (37–79°).
- **Решение:** задавать локоть углом сгиба из видео, крутить плечо по плоскости сгиба только при заметном сгибе.
