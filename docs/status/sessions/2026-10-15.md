# 2026-10-15 — Studio с телефона через Tailscale

Задача Ильи: открывать `./xms gui` с телефона через Tailscale и загружать видео из медиатеки телефона.

## Что сделано (уровень: *функционально проверено* в облачном контейнере, на Маке и iPhone не проверено)

- `./xms gui --tailscale` (или `XMS_GUI_TAILSCALE=1`, или `Xandra Studio (Tailscale).command`) — сервер слушает 127.0.0.1 **и** Tailscale-адрес Мака на порту 8765 и печатает URL (IP и MagicDNS-имя). Адрес ищется через `tailscale ip -4` (CLI в PATH или внутри `/Applications/Tailscale.app`), иначе по `ifconfig` в диапазоне 100.64.0.0/10.
- `--host IP` добавляет явный адрес; `0.0.0.0`/`::` отклоняются — молча в LAN не открываемся.
- С не-loopback клиента «Выбрать видео» открывает `<input type=file accept=video/*>` (на iOS — медиатека/Файлы), файл потоково загружается `POST /api/upload` в `runs/uploads/<sha256[:12]>-<имя>`; прогресс загрузки в процентах. Лимит 8 ГБ (`XMS_GUI_MAX_UPLOAD_MB`), проверка свободного места, битый/не-видео файл удаляется.
- `/api/pick` и `/api/open` с удалённого клиента отклоняются (открыли бы окно на Маке). На телефоне «Открыть видео» / «Сравнение» играют результат в браузере.
- Размер видео в UI учитывает поворот (портретное видео iPhone показывается 1080 × 1920).

## Проверка

- Сервер на 127.0.0.1 + второй адрес контейнера: загрузка HEVC 10-bit `.MOV` с rotation=90 (12 МБ) — принято, 1080 × 1920, 20 с; 610 МБ — 8 с, память сервера ~39 МБ; `.sh` и не-видео отклонены; токен обязателен; `Content-Type: video/quicktime` и Range для просмотра.
- Headless Chromium с эмуляцией iPhone 13: выбор файла → загрузка → кнопка Run активна.
- `tests/test_gui.py`: +2 теста (адреса/диапазон Tailscale, загрузка: имя, дедупликация, обрыв, лимит).

## Не проверено

- Реальный Мак с Tailscale и Safari на iPhone. iOS при выборе из медиатеки может отдать перекодированную копию (H.264) вместо оригинала HEVC — это решает iOS, не сервер.
- Полный прогон пайплайна на видео, загруженном с телефона.
