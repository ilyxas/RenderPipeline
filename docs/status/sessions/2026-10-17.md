## Регистрация ассетов: реестр и панель в Студии (уровень: *функционально проверено*)

**Причина ошибки «asset hash mismatch».** `.xms/config.json` хранит пути к профилю и к `.blend` независимо. Ручная правка (15:49) поставила `loft/v3` вместе с `Loft_Studio_v10.blend`. Конфиг восстановлен на `loft/v4`, бэкап лежит в `.voyager/tmp`.

**Исправление на уровне системы.**
- `src/xms/registry.py`:
  - `status` — текущая пара, вердикт словами, все версии профилей и файл с подходящим хешем, незарегистрированные `.blend`. Хеши кэшируются по size+mtime в `.xms/hash-cache.json`.
  - `use` — записывает в конфиг только согласованную пару «профиль + его файл»; бэкап в `.xms/backups/`.
  - `register` — новая версия vN+1 копией базового профиля. Старые версии не меняются. Перед регистрацией в Blender проверяется (`blender/check_registration.py`, только чтение):
    - персонаж: те же кости, иерархия, rest pose, положение арматуры, формы лица, `pose_position=POSE`;
    - сцена: коллекция и мир.
- Пайплайн при несовпадении теперь пишет, какая сторона не сошлась и какой профиль подходит к файлу.
- Студия:
  - карточка «00 Персонаж и сцена» (выбор профиля, ✓/✗, кнопка «Зарегистрировать» для новых или изменённых `.blend`);
  - в шапке показывается текущая пара вместо зашитого «Xandra / Bedroom»;
  - Run заблокирован, пока пара не сходится;
  - пока идёт запуск, регистрация недоступна.
- CLI: `xms assets status|use NAME|register FILE --base NAME`.
